# Security Policy

## Reporting a Vulnerability

If you believe you've found a security vulnerability in `chowbea`, please report it **privately** rather than opening a public issue.

**Preferred channel:** open a private security advisory on GitHub:

> https://github.com/ToniChowBea/chowbea/security/advisories/new

Alternatively, email **platforms@chowbea.com** with the subject line `[security] chowbea`.

Please include:

- A description of the issue and its potential impact
- Steps to reproduce, ideally with a minimal proof-of-concept
- The version of `chowbea` affected (e.g. `3.0.0`), or of the `chowbea-axios` compatibility package
- Your assessment of severity, if known

### Response timeline

| Stage | Target |
|---|---|
| Acknowledgement | **Within 7 days** of receiving the report |
| Initial triage and severity assessment | Within 14 days |
| Fix released or mitigation published | Best effort — typically within 30 days for High/Critical; longer for low-severity issues that require breaking changes |
| Public disclosure | Coordinated with the reporter, usually once a fix is available on the latest supported alpha |

We will keep you informed throughout the process. If we determine the issue is out of scope (e.g. it affects a dependency we don't ship, or a configuration the user controls), we will explain why.

## Supported Versions

| Version | Supported |
|---|---|
| Latest `chowbea` `3.x` (published as `latest`) | ✅ |
| Latest `chowbea-axios` `3.x` (compatibility shim) | ✅ — it re-exports `chowbea`, so fixes land with the dependency |
| Latest `chowbea-axios` `2.x` | ⚠️ Critical security fixes only, until 2027-02-15 |
| Older `2.x` / `3.x` releases | ❌ — fix forward by upgrading |
| `2.0.0-alpha.*` prereleases | ❌ — superseded by `2.0.0` stable |
| `1.x` and earlier | ❌ |

We support **only the latest release** on the `latest` dist-tag. Security fixes ship as patch versions (e.g. `3.0.1`); older releases do not receive backports. The recommended response to a security advisory is to upgrade.

`chowbea-axios` `2.x` receives critical security fixes for six months after the `3.0.0` release (until **2027-02-15**). The upgrade path is deliberately cheap: `3.x` is the same tool under a new package name, the `chowbea-axios` command still ships, and the `chowbea-axios` package continues to work as a shim — so upgrading is a dependency change, not a code change.

## Scope

In-scope:

- The published `chowbea` CLI and its runtime (parsing user-controlled OpenAPI specs, generating TypeScript code, writing to the filesystem)
- The `chowbea-axios` compatibility package and the `chowbea-axios` command alias
- The Type Bus: the `extract` pass, the `chowbea/api` request handler, and the validation applied to manifests fetched over the network before they are emitted as TypeScript
- The TypeScript code generated by the CLI (e.g. injection or type-safety issues introduced at codegen time)
- The Vite plugin templates exported via `chowbea/vite`
- The CI template shipped under `templates/`

Out of scope:

- Vulnerabilities in user-supplied OpenAPI specs themselves (we sanitize what we emit, but we don't validate spec correctness beyond what's needed for generation)
- Configurations the user explicitly opts into (e.g. an `output.folder` pointing at a sensitive directory)
- Vulnerabilities in transitive dependencies — please report those upstream first; we will track the advisory and bump pinned versions as fixes become available
- Issues affecting end-of-life or unsupported versions (see table above)

## Acknowledgements

Reporters who follow this policy will be credited in the release notes for the fix (unless they request anonymity).
